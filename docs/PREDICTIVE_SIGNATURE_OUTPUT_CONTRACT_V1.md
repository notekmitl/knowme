# Predictive Signature Output Contract V1

## Deterministic identity

A predictive signature consists only of the resolved prediction inputs that are authorized to select reader copy:

1. resolved Mahabhut context;
2. applicable age and current life-period selector;
3. ordered, serialized typed forecast materials and their evidence keys;
4. available source/evidence bindings required by each semantic owner.

Two Known-time analyses with the same signature must produce identical predictive section IDs, section order and predictive text. Birth date, birth clock time, province, gender, ascendant degree and a pinned test date are not editorial selectors.

Calculated report identity remains independent of predictive-copy identity. A change in birth time may therefore change the displayed time, ascendant degree and factual provenance without changing the predictive body when the predictive signature remains equal.

## Rule selection

- Rules are selected by context, period and typed-material/evidence bindings.
- Each emitted prediction clause identifies its semantic owner and input-bound evidence.
- A signature-specific approved component set is not a fixture override: it applies to every input resolving to that signature.
- Candidate 0023 is the approved component set for context `mahabhut2537.rem0.saturday`, age 44, selector `venus.42_62` and the recorded 12-material fingerprint.
- Other signatures continue through their own generalized rules; Candidate 0023 is never a generic fallback.
- Missing required evidence causes omission rather than invented text.

## Historical oracle

Candidate 0011 remains immutable historical evidence with its original Owner acceptance and hash. It is no longer a production runtime selector for the 00:03 fixture. Tests preserve its bytes and acceptance record, while runtime tests enforce the active signature contract.

## Unknown-time boundary

Unknown-time input cannot establish the Known predictive signature. It must omit ascendant, houses, Thai astrological day, time-dependent fields, life-period and future-prediction output, and it must never substitute Candidate 0011 or Candidate 0023.

## Negative controls

Validation must reject production branches or copy-selection keys based on fixture name/profile ID, birth date, clock time, province, gender, ascendant degree or pinned `asOf`, and must reject static full-report or exact-candidate shortcuts.
