# Thai Mahabhut Predictive Canon V2 Charter

Date: 2026-08-30

Status: **OWNER-AUTHORIZED MODELING PROGRAM — DESIGN / SOURCE EXTRACTION ONLY**

## Authority order

1. Tier 0 — KnowMe calculation engine: astronomical and deterministic
   calculation facts only.
2. Tier 1 — `หลักมหาภูต ฉบับสมบูรณ์ — ส. หยกฟ้า`: interpretation and
   predictive authority.
3. Tier 2 — traceable Thai classical sources: support only.
4. Tier 3 — research corpus: support only.
5. Tier 4 — general internet material: lowest support tier.

Tier 2–4 never override Tier 1. A disagreement must be retained as an explicit
conflict. Owner approval replaces the prior need for an external astrologer;
it does not allow Codex to invent rules.

OR3 NO-GO remains binding for self-authored heuristics, blanket
`currentAge + 1`, unsupported event movements and thresholds 64, 68, 46, 75
or 80. This Charter reopens only source-backed modeling gaps.

## Opened scope

- pp.17–18: rise/fall and age-period rules;
- p.39: compound Taksa role meanings;
- pp.40–41: general prediction rules and Kalakini exceptions;
- pp.44–292: archetype/day/life-period examples and narrative effects;
- prediction-related post-freeze OCR recovery;
- traceable alternative readings and source conflicts.

## Out of scope

- remedies, mantras or ritual procedure unrelated to prediction;
- personality or psychological conclusions as primary content;
- UI, runtime wiring, report generation, tests of runtime output or engine
  changes made to fit a Candidate;
- new actors, events, amounts, dates, frequencies or thresholds not stated in
  source;
- `product-acceptance/`, Firebase, Production, deployment, merge or Ready for
  Review.

## Edition and provenance rule

The available extraction scan is the 2537 complete edition. The
Owner-designated authority is the 2539 reprint. Until direct page mapping is
complete, every rule must carry the 2537 edition ID and may not claim 2539 page
provenance. The edition mismatch is a promotion blocker, not permission to
copy page numbers across editions.

## Statement-type policy

| Type | Permitted use |
|---|---|
| `GENERAL_RULE` | General use only when all source conditions are met |
| `CONDITIONAL_RULE` | Use only when every required condition is proven |
| `EXCEPTION_RULE` | Overrides the affected general rule exactly as source states |
| `ARCHETYPE_EXAMPLE` | Example-only; never generalized |
| `LIFE_PERIOD_EXAMPLE` | Only when archetype, Thai-day, period and age context match |
| `NARRATIVE_OBSERVATION` | No runtime use until source conditions are modeled |
| `SUPPORTING_RESEARCH_ONLY` | Support/contrast only; never Tier 1 authority |

## Safety and promotion gates

A proposed rule must include edition, page, section, a short checked excerpt,
conditions, allowed conclusion, prohibited escalation, certainty, timing,
exception/conflict behavior and review state. `EXAMPLE_ONLY`, OCR-blocked,
ambiguous or edition-unmapped entries cannot become general runtime rules.

The proposed corpus is not runtime Canon. Promotion requires Owner review,
edition mapping, schema/trace validation, conflict closure and a separate
implementation authorization. `monthlyTimelineAvailable=false` remains
unchanged unless a Tier 1 rule gives a real within-year boundary.
